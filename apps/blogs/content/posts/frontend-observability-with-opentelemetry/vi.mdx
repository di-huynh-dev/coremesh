## Observability không chỉ là bắt lỗi

Error tracking trả lời câu "cái gì vừa throw?". Observability trả lời câu "vì sao trải nghiệm của người dùng này tệ?", bao gồm cả những thứ không hề throw: tương tác chậm, layout giật, một request thành công nhưng mất 9 giây. Phần phân loại và báo cáo lỗi mình đã viết trong [bài về xử lý lỗi](/blog/frontend-error-handling-strategy); bài này nói về mọi thứ còn lại.

Có hai nguồn dữ liệu bổ sung cho nhau:

| | Synthetic monitoring | Real User Monitoring (RUM) |
| --- | --- | --- |
| Ai tạo dữ liệu | Một bot chạy script trên thiết bị và mạng cố định | Mọi phiên truy cập thật |
| Mạnh ở | Uptime, bắt regression trong CI, baseline trước khi ra mắt | Phân bố thật của thiết bị, mạng, hành trình người dùng |
| Mù với | Đuôi dài, script bên thứ ba chạy khác đi, hành vi thật | Trang chưa ai vào, mọi thứ trước khi ship |
| Chi phí tăng theo | Số check × tần suất | Traffic × tỉ lệ sampling × kích thước payload |

Mình chạy vài synthetic check cho các hành trình sống còn (đăng nhập, tìm kiếm, checkout) để biết sự cố lúc 3 giờ sáng trước người dùng, còn lại dùng RUM.

## Nên thu thập gì ở trình duyệt

Cám dỗ lớn nhất là thu thập tất cả. Đừng: mỗi attribute thêm vào đều nhân chi phí lưu trữ và cardinality. Bộ mặc định của mình:

- **Core Web Vitals kèm attribution.** Không chỉ con số, mà cả phần tử LCP và các pha của nó, target của INP cùng phần input delay, processing, presentation, và nguồn gây CLS. Cơ chế chi tiết nằm ở [bài Core Web Vitals](/blog/core-web-vitals); ở đây chúng trở thành attribute của span, gắn theo route.
- **Long animation frames (LoAF).** Bản kế nhiệm của Long Tasks: cho biết script nào (URL, tên hàm, invoker) làm frame bị chậm. Theo những gì mình kiểm chứng được thì nó mới có trên Chromium, nên hãy coi nó là một mẫu của sự thật chứ không phải toàn cảnh.
- **Resource timing cho những thứ quan trọng.** Không phải mọi ảnh, chỉ các API call, bundle chính và font quan trọng, kèm `transferSize` và `nextHopProtocol` để phát hiện cache miss hay bị rơi về HTTP/1.1.
- **Span cho hành trình người dùng.** "Mở giỏ hàng → thanh toán xong" là một span, mỗi fetch bên trong là span con.

LoAF cần kiểm tra hỗ trợ và một type cục bộ, vì không phải phiên bản `lib.dom` nào của TypeScript cũng có sẵn:

```ts
type LongAnimationFrameScript = {
  sourceURL: string;
  sourceFunctionName: string;
  invoker: string;
  duration: number;
};

type LongAnimationFrameEntry = PerformanceEntry & {
  blockingDuration: number;
  scripts: LongAnimationFrameScript[];
};

export function observeLongAnimationFrames(report: (entry: LongAnimationFrameEntry) => void) {
  if (!PerformanceObserver.supportedEntryTypes.includes("long-animation-frame")) return;
  new PerformanceObserver((list) => {
    for (const entry of list.getEntries() as LongAnimationFrameEntry[]) {
      if (entry.blockingDuration > 100) report(entry);
    }
  }).observe({ type: "long-animation-frame", buffered: true });
}
```

## OpenTelemetry trong trình duyệt năm 2026

OpenTelemetry cho bạn một data model trung lập với vendor (trace, metric, log) và định dạng truyền OTLP, nên đổi backend mà không phải viết lại instrumentation. Trên web, tình trạng thật ở thời điểm cuối 2026:

- Các package tracing cốt lõi cho web, `@opentelemetry/sdk-trace-web` cùng `@opentelemetry/instrumentation-fetch` và các instrumentation khác, chạy được và được dùng rộng rãi, nhưng các package instrumentation vẫn ở phiên bản 0.x và API vẫn thay đổi giữa các bản phát hành.
- Browser SIG đang xây một browser SDK và bộ browser instrumentation riêng trong một repository tách biệt. Các package đó còn experimental; mình chưa dám đặt cược một đợt rollout production vào API của chúng.
- Đã có semantic convention riêng cho trình duyệt (ví dụ các resource attribute `browser.*`), nhưng phần lớn mảng RUM, như cách mô hình hoá một Web Vital hay một hành động của người dùng, vẫn ở trạng thái development hoặc experimental. Hãy pin version và chuẩn bị tinh thần cho việc đổi tên.

Quan điểm thực tế của mình: dùng **data model và convention** của OpenTelemetry trong trình duyệt, kể cả khi không dùng nguyên bộ SDK. SDK chính thức cộng context manager dựa trên zone làm bundle nặng thêm đáng kể, trong khi chính bạn đang cố bảo vệ LCP của trang. Một tracer nhỏ tự viết, phát ra span với cùng kiểu ID, tên và key attribute (`http.request.method`, `url.full`, `http.response.status_code`) đã cho 80% giá trị, và collector có thể chuyển nó sang OTLP.

## Một trace từ cú click đến database

Tính năng đáng giá nhất là propagation. Header `traceparent` của W3C Trace Context mang version, trace ID 16 byte, parent span ID 8 byte và flags (bit thấp nhất nghĩa là "được sample"). Nếu trình duyệt gửi header này kèm fetch, backend có OpenTelemetry sẽ tiếp tục đúng trace đó, và các span database trở thành cháu của cú click của bạn.

Đây là span helper mình hay dùng làm điểm xuất phát. Quyết định sampling được đưa ra một lần cho mỗi session, nên mọi span của một session hoặc cùng được giữ, hoặc cùng bị bỏ:

```ts
export type SpanRecord = {
  traceId: string;
  spanId: string;
  parentSpanId?: string;
  name: string;
  startTime: number;
  endTime?: number;
  status: "unset" | "ok" | "error";
  attributes: Record<string, string | number | boolean>;
};

export type SpanHandle = ReturnType<typeof startSpan>;

const sessionSampled = Math.random() < 0.1;

function randomHex(byteLength: number): string {
  const bytes = crypto.getRandomValues(new Uint8Array(byteLength));
  return Array.from(bytes, (byte) => byte.toString(16).padStart(2, "0")).join("");
}

function nowEpochMs(): number {
  return performance.timeOrigin + performance.now();
}

export function startSpan(name: string, parent?: SpanRecord) {
  const span: SpanRecord = {
    traceId: parent?.traceId ?? randomHex(16),
    spanId: randomHex(8),
    parentSpanId: parent?.spanId,
    name,
    startTime: nowEpochMs(),
    status: "unset",
    attributes: {},
  };

  return {
    span,
    setAttribute(key: string, value: string | number | boolean) {
      span.attributes[key] = value;
    },
    traceparent(): string {
      return `00-${span.traceId}-${span.spanId}-${sessionSampled ? "01" : "00"}`;
    },
    end(status: "ok" | "error" = "ok") {
      if (span.endTime !== undefined) return;
      span.endTime = nowEpochMs();
      span.status = status;
      if (sessionSampled || status === "error") enqueueSpan(span);
    },
  };
}

let activeJourney: SpanHandle | undefined;

export function startJourney(name: string): SpanHandle {
  activeJourney = startSpan(`journey.${name}`);
  return activeJourney;
}

export function endJourney(status: "ok" | "error" = "ok") {
  activeJourney?.end(status);
  activeJourney = undefined;
}

export function currentJourney(): SpanRecord | undefined {
  return activeJourney?.span;
}
```

Và phần instrument fetch. Nó chỉ chèn header cho những origin mình cho phép rõ ràng, và bỏ qua chính endpoint telemetry để tránh đệ quy:

```ts
const telemetryPath = "/api/rum";
const propagationOrigins = new Set([location.origin, "https://api.example.com"]);

export function instrumentFetch() {
  const originalFetch = window.fetch.bind(window);

  window.fetch = async (input: RequestInfo | URL, init?: RequestInit) => {
    const request = new Request(input, init);
    const url = new URL(request.url);
    if (url.origin === location.origin && url.pathname === telemetryPath) {
      return originalFetch(request);
    }

    const handle = startSpan(`HTTP ${request.method}`, currentJourney());
    handle.setAttribute("http.request.method", request.method);
    handle.setAttribute("url.full", `${url.origin}${url.pathname}`);
    if (propagationOrigins.has(url.origin)) {
      request.headers.set("traceparent", handle.traceparent());
    }

    try {
      const response = await originalFetch(request);
      handle.setAttribute("http.response.status_code", response.status);
      handle.end(response.ok ? "ok" : "error");
      return response;
    } catch (error) {
      handle.setAttribute("error.type", error instanceof Error ? error.name : "unknown");
      handle.end("error");
      throw error;
    }
  };
}
```

Lưu ý `url.full` cố tình bỏ query string; chi tiết ở phần PII. Ở backend, bất kỳ OpenTelemetry SDK nào dùng propagator W3C mặc định và sampler kiểu parent-based đều tôn trọng cờ sampled, nên trình duyệt quyết định và server làm theo.

### CORS: cái header làm sập production

`traceparent` không nằm trong danh sách header được CORS coi là an toàn. Ngay khi bạn thêm nó vào một request cross-origin, trình duyệt sẽ gửi preflight `OPTIONS`, và nếu API không liệt kê nó trong `Access-Control-Allow-Headers` thì request thật sẽ thất bại. API của bạn phải trả lời preflight với kiểu như `Access-Control-Allow-Headers: content-type, authorization, traceparent, tracestate`, và tốt nhất là có `Access-Control-Max-Age` hợp lý để không tốn thêm một round trip cho mỗi lần gọi.

<Callout type="danger">
  Đừng bao giờ truyền trace header sang origin bên thứ ba (cổng thanh toán, analytics, CDN bạn không kiểm soát). Vì vậy helper ở trên dùng allowlist origin, cùng ý tưởng với tuỳ chọn `propagateTraceHeaderCorsUrls` của OpenTelemetry fetch instrumentation.
</Callout>

## Gửi dữ liệu mà không mất batch cuối

Telemetry thú vị nhất (INP cuối cùng, hành trình bị bỏ dở) xảy ra ngay trước khi người dùng rời trang. `unload` không đáng tin và còn chặn back/forward cache, nên hãy flush khi `visibilitychange` chuyển sang hidden và khi `pagehide`. Dùng `navigator.sendBeacon` hoặc `fetch` với `keepalive: true`: cả hai đều sống sót khi trang biến mất, và cả hai đều bị giới hạn khoảng 64 KB body đang gửi dở cho mỗi trang. Vì thế batch phải được giới hạn theo byte:

```ts
const maxBatchBytes = 60_000;
const maxBatchSpans = 50;
const flushDelayMs = 5_000;

let pendingSpans: SpanRecord[] = [];
let flushTimer: ReturnType<typeof setTimeout> | undefined;

export function enqueueSpan(span: SpanRecord) {
  pendingSpans.push(span);
  if (pendingSpans.length >= maxBatchSpans) {
    flushSpans(false);
    return;
  }
  flushTimer ??= setTimeout(() => flushSpans(false), flushDelayMs);
}

function takeBatch(): SpanRecord[] {
  const batch: SpanRecord[] = [];
  let batchBytes = 0;
  while (pendingSpans.length > 0) {
    const spanBytes = JSON.stringify(pendingSpans[0]).length;
    if (batch.length > 0 && batchBytes + spanBytes > maxBatchBytes) break;
    batch.push(pendingSpans.shift() as SpanRecord);
    batchBytes += spanBytes;
  }
  return batch;
}

function flushSpans(pageIsHiding: boolean) {
  clearTimeout(flushTimer);
  flushTimer = undefined;
  while (pendingSpans.length > 0) {
    const body = JSON.stringify({ spans: takeBatch() });
    const beaconQueued =
      pageIsHiding && navigator.sendBeacon(telemetryPath, new Blob([body], { type: "application/json" }));
    if (!beaconQueued) {
      fetch(telemetryPath, {
        method: "POST",
        body,
        keepalive: true,
        headers: { "content-type": "application/json" },
      }).catch(() => undefined);
    }
  }
}

document.addEventListener("visibilitychange", () => {
  if (document.visibilityState === "hidden") flushSpans(true);
});
window.addEventListener("pagehide", () => flushSpans(true));
```

Hai chi tiết từng làm mình khổ. Thứ nhất, giữ endpoint cùng origin (proxy sang collector): một beacon cross-origin với content type JSON cần CORS, và beacon không xử lý preflight một cách êm ái. Thứ hai, `sendBeacon` trả về `false` khi trình duyệt từ chối xếp hàng dữ liệu, thường do vượt quota kích thước; đó là tín hiệu để fallback, không phải để retry trong vòng lặp.

## Sampling và chi phí

Chi phí RUM tăng theo traffic, và một site đông người dùng sinh ra rất nhiều span. Mình kết hợp mấy chiến lược:

- **Head sampling theo session**, như ở trên. 5–20% là đủ cho dashboard p75 ở hầu hết sản phẩm; sample theo session (không phải theo span) giữ cho hành trình không bị cắt vụn.
- **Luôn giữ lỗi.** Helper vẫn export span lỗi kể cả từ session không được sample.
- **Tail sampling ở collector** cho phần còn lại: giữ trọn các trace chậm và trace lỗi, bỏ phần lớn các trace nhanh nhàm chán. Việc này cần một OpenTelemetry Collector đứng giữa trình duyệt và vendor.
- **Để ý cardinality, không chỉ volume.** Một `url.full` có ID trong path sẽ biến thành hàng triệu series khác nhau. Chuẩn hoá về route template (`/orders/[id]`) trước khi nó thành attribute dùng để group.

## PII, consent và niềm tin

Telemetry là dữ liệu cá nhân ngay khi nó có thể nhận diện ai đó. Quy tắc của mình: bỏ query string và fragment khỏi mọi URL (token reset mật khẩu và email hay nằm ở đó), không bao giờ ghi giá trị input hay nội dung text, dùng session ID ngẫu nhiên thay cho user ID, và lọc lại lần nữa ở collector vì code phía client không phải lớp phòng thủ cuối cùng. Hàm `scrub` trong bài xử lý lỗi dùng được cho attribute của span.

Chuyện consent phụ thuộc vào luật nơi bạn hoạt động và team pháp lý, không phải mình, nhưng phần kỹ thuật thì giống nhau: chỉ khởi tạo telemetry sau khi có consent ở nơi luật yêu cầu, đưa cờ sampling vào quyết định đó, và giữ một kill switch để tắt RUM mà không cần deploy.

## Tích hợp vào Next.js 16

Next.js có file `instrumentation-client.ts` (ở thư mục gốc dự án hoặc trong `src`): code trong đó chạy sau khi HTML tải xong và trước khi React hydrate, đúng chỗ RUM nên bắt đầu. File này cũng có thể export `onRouterTransitionStart`, được gọi mỗi lần điều hướng phía client, rất hợp để mở một span điều hướng. Ở phía server, `instrumentation.ts` với hàm `register()` thiết lập OpenTelemetry cho route handler và server component, ví dụ qua `@vercel/otel` hoặc Node SDK, để nửa backend của trace tồn tại.

```ts
import { onINP, onLCP } from "web-vitals/attribution";
import { endJourney, instrumentFetch, startJourney, startSpan } from "./lib/rum";
import { observeLongAnimationFrames } from "./lib/loaf";

instrumentFetch();

onINP((metric) => {
  const handle = startSpan("web_vital.inp");
  handle.setAttribute("web_vital.value", metric.value);
  handle.setAttribute("web_vital.rating", metric.rating);
  handle.setAttribute("inp.target", metric.attribution.interactionTarget);
  handle.setAttribute("inp.input_delay", metric.attribution.inputDelay);
  handle.setAttribute("inp.processing", metric.attribution.processingDuration);
  handle.setAttribute("inp.presentation", metric.attribution.presentationDelay);
  handle.end();
});

onLCP((metric) => {
  const handle = startSpan("web_vital.lcp");
  handle.setAttribute("web_vital.value", metric.value);
  handle.setAttribute("lcp.target", metric.attribution.target ?? "unknown");
  handle.end();
});

observeLongAnimationFrames((entry) => {
  const worstScript = entry.scripts.toSorted((a, b) => b.duration - a.duration)[0];
  const handle = startSpan("browser.long_animation_frame");
  handle.setAttribute("loaf.blocking_duration", entry.blockingDuration);
  handle.setAttribute("loaf.script_url", worstScript?.sourceURL ?? "unknown");
  handle.end();
});

export function onRouterTransitionStart(url: string, navigationType: "push" | "replace" | "traverse") {
  endJourney();
  const journey = startJourney("navigation");
  journey.setAttribute("navigation.type", navigationType);
  journey.setAttribute("url.path", new URL(url, location.origin).pathname);
}
```

Các tên attribute như `web_vital.*` và `loaf.*` là do mình tự đặt; cho đến khi convention cho trình duyệt ổn định, hãy chọn một namespace, ghi tài liệu và giữ nó ổn định. Đoạn code trên là `instrumentation-client.ts`; hãy giữ các module được import thật nhỏ, vì mọi thứ ở đây chạy trước hydrate và tranh tài nguyên với LCP của bạn.

## Tóm tắt

<Checklist>

- Error tracking cho biết cái gì throw; observability cho biết vì sao trải nghiệm tệ. Bạn cần cả hai, cộng vài synthetic check cho hành trình sống còn.
- Thu thập Web Vitals kèm attribution, long animation frames, một số resource timing chọn lọc và span cho hành trình người dùng; đừng thu thập mọi thứ.
- Data model của OpenTelemetry và `traceparent` của W3C là nền vững; browser SDK và convention cho RUM vẫn experimental, nên pin version hoặc giữ một tracer mỏng.
- Chỉ truyền `traceparent` tới allowlist origin của chính bạn, và cấu hình API cho phép header này trong preflight CORS.
- Flush khi `visibilitychange` và `pagehide` bằng `sendBeacon` hoặc fetch `keepalive`, theo batch dưới 64 KB, tới endpoint cùng origin.
- Sample theo session, luôn giữ lỗi, tail-sample ở collector, và chuẩn hoá URL về route template.
- Bỏ query string, không ghi giá trị input, tôn trọng consent, và luôn có kill switch.
- Với Next.js 16, khởi động RUM trong `instrumentation-client.ts` và trace server trong `instrumentation.ts` để một trace xuyên suốt trình duyệt, API và database.

</Checklist>
